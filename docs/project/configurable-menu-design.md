# 可配置增强菜单：设计草案

状态：已按用户的实施要求落实到 `0.2.0`。本文取代[首版 Spec](spec.md)和[首版设计](design.md)中“Alert 平铺于单层菜单”及“没有设置页”的交互约定；保留 GitHub 原生编辑器的原则不变。实际验证范围以[本版验收记录](acceptance-0.2.0.md)为准。

## 目标与边界

当前增强菜单把五种 Alert 与 Details、Keyboard、Diff 平铺，并在每个选项后附一段说明，列表较长。新设计把五种 Alert 收进同一类别，在菜单内使用图标和短名称；详细解释移至悬停提示及设置页。用户可以配置命令的显示及顺序，创建 Markdown 模板命令，并调整**扩展界面**的字号。

每个合格的 GitHub 编辑器仍有自己的增强按钮。选择命令只编辑该实例的原生正文；GitHub 的 Write / Preview、文件预览、输入、撤销及提交仍由 GitHub 负责。设置全局作用于当前浏览器配置文件中的所有 GitHub 仓库，不跨设备同步，不记录正文或选区。目标浏览器为 Chrome 和 Edge。

## 菜单信息架构

```text
GitHub 原生按钮…… [增强图标 ▾]
                    ┌─────────────────────┐
                    │ ⓵ Alert           › │  ← 点击或键盘进入
                    │ ◫ Details            │
                    │ ⌨ Keyboard           │
                    │ ± Diff               │
                    │ ◇ 自定义           › │  ← 有启用项时显示
                    └─────────────────────┘

同一弹层切换到 Alert 页：       同一弹层切换到自定义页：
┌─────────────────────┐        ┌─────────────────────┐
│ ‹ 返回    Alert       │        │ ‹ 返回    自定义      │
│ ⓘ Note              │        │ ◇ 用户的命令一       │
│ ◇ Tip               │        │ ▣ 用户的命令二       │
│ ! Important         │        └─────────────────────┘
│ △ Warning           │
│ ⛔ Caution           │
└─────────────────────┘
```

示意图只表达层级，不规定最终 SVG 形状。按钮沿用现有图标入口与 GitHub 工具栏的尺寸关系，不放一长串英文。命令行同时显示图标和短名称；颜色不单独承担语义。命令说明放在 `title` / 辅助文本及设置页，不占据菜单正文。具体图标需在浅色、深色与高对比主题下能辨认；自定义命令只能从扩展自带图标集合选取，不接收任意 SVG 或脚本。

一级只有 Alert 是内置类别；Details、Keyboard、Diff 保持一级操作。自定义命令统一放在“自定义”二级页，避免自定义数量增加后撑长根菜单。用户可分别调整一级内置项的顺序、五种 Alert 的顺序、自定义命令的顺序；隐藏的命令不出现在菜单中。Alert 若没有启用子项，其类别不显示。自定义若没有启用子项，其类别不显示。类别本身不写入编辑器。全部命令都隐藏时不挂载网页增强按钮；浏览器扩展图标和选项页仍可用于重新启用命令。

点击类别或按 Enter、Space、右方向键进入；进入后焦点落在第一个可用命令。二级页顶部有“返回”操作，左方向键或 Escape 返回一级；一级 Escape 关闭菜单并把焦点交还增强按钮。上下方向键、Home、End 在当前页移动；Tab 离开菜单并遵守页面焦点顺序。打开菜单时保留原有目标编辑器与选区快照，进入二级页不重新选择目标；若编辑器内容、选区或实例失效，取消本次插入并提示重新打开。菜单仍按当前 Issue 弹窗/README 页面定位，不因切换二级页出现页面跳动或越界。交互可参照 [WAI-ARIA 菜单按钮模式](https://www.w3.org/WAI/ARIA/apg/patterns/menu-button/)及[子菜单键盘模式](https://www.w3.org/WAI/ARIA/apg/patterns/menubar/)，最终以实际语义和键盘验收为准。

## 设置入口与页面

设置只从浏览器扩展图标或浏览器扩展管理页的“选项”进入；GitHub 页面内的增强菜单不放“设置”。现有扩展即使未声明 `action` 也会出现在扩展中心，但当前 `manifest.json` 只有内容脚本，点击图标不会自动打开自定义设置页。新版本声明 `action`、选项页，并把图标点击接到 `runtime.openOptionsPage()`；不设 `default_popup`，以免点击事件被弹窗占用。图标是否固定显示在浏览器工具栏由用户决定，扩展中心仍可进入。[Chrome Action API](https://developer.chrome.com/docs/extensions/reference/api/action) · [Chrome 选项页](https://developer.chrome.com/docs/extensions/develop/ui/options-page)

设置页按下列任务组织，所有编辑都只改变扩展配置，不读取或修改当前 GitHub 正文：

| 区域 | 可操作内容 | 固定约束 |
| --- | --- | --- |
| 内置命令 | 显示/隐藏；调整一级项和 Alert 内部顺序 | 内置项不能删除，模板内容不能改写 |
| 自定义命令 | 新建、编辑、删除、显示/隐藏、排序、挑选内置图标 | 只接受 Markdown 文本模板，不运行 JavaScript；有明确数量与长度上限 |
| 外观 | 调整扩展菜单和选项页字号；恢复默认字号 | 12–20 px，默认 14 px，步长 1 px；不改 GitHub 原生编辑器字号 |
| 备份 | 导出 JSON；导入前显示影响预览 | 用户确认后整体替换 |

字号输入和配置导入都在保存前校验；范围外字号不保存。菜单应在浏览器 200% 缩放和窄窗口下可滚动、可操作，字号设置不意味着可以绕过浏览器缩放。[WCAG 2.2 字体缩放说明](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)

## 自定义模板契约

自定义命令包含稳定 ID、短名称、所选内置图标、Markdown 模板、显示状态及顺序。设置页给出模板预览与占位符帮助，但插入后的实际渲染由 GitHub 原生 Preview 验证。最多保存 50 条自定义命令，名称最多 40 个字符，模板最多 10 KB；达到上限时直接说明是哪一项超限。字符计数和字节计数在页面上明确标注，导入使用相同上限。

只支持两个标记：

| 标记 | 插入时的含义 |
| --- | --- |
| `{{selection}}` | 替换为目标编辑器当前选中文字；无选区则为空文本 |
| `{{cursor}}` | 不输出字符，指定插入后光标位置；最多出现一次 |

例如模板 `**{{selection}}{{cursor}}**` 在选中 `重要` 时输出 `**重要**`，光标位于被选文字之后、闭合星号之前。有选区但模板未使用 `{{selection}}` 时，按编辑器通常的替换语义用模板覆盖选区；不能暗中把原文附加到模板。若模板没有 `{{cursor}}`，插入后光标位于本次输出末尾。自定义命令沿用当前目标实例、选区快照与原生写入/撤销契约；不能因为模板存在就另建编辑器或执行脚本。

保存前严格解析双花括号标记：只允许上述名称，`{{cursor}}` 最多一次；未闭合标记、拼写错误或不支持的变量显示错误位置并阻止保存。导入配置也必须执行同一验证，不能借导入绕过限制。模板仅作为纯文本生成 Markdown；菜单、设置页和错误信息应使用安全的文本呈现，不把模板当 HTML 注入页面。[Chrome 扩展安全建议](https://developer.chrome.com/docs/extensions/develop/security-privacy/stay-secure)

## 配置与生命周期

配置存在扩展的本地存储中，包含显式的配置版本、内置命令的可见性/排序、自定义命令、扩展字号。配置不按仓库分叉，也不用跨设备同步；卸载扩展会丢失本地配置，JSON 导出用于用户备份。扩展只需为此增加 `storage` 权限；不需要 GitHub Token、远程服务、剪贴板、`tabs` 或宽泛站点权限。[Chrome Storage API](https://developer.chrome.com/docs/extensions/reference/api/storage)

选项页、内容脚本应使用同一验证规则。新安装或缺失字段时读取默认值；`0.1.0` 没有持久化配置，因此本版从配置版本 1 开始；未来版本需要显式迁移，当前对未知版本直接报错。配置损坏时选项页提示并使用内置默认值；导入不合法时保留当前配置。通过存储变更事件将设置立即同步至已打开的 GitHub 页面；若增强菜单正打开，先关闭并失效旧选区快照，再根据新配置构建下一次菜单。配置变化只影响扩展按钮与菜单，不能触发 Markdown 插入或修改正在编辑的正文。

导出的 JSON 应包含配置版本和全部用户可配置字段，不包含 GitHub 正文、选区、页面 URL、Cookie 或浏览器内部信息。导入流程为选文件 → 解析与校验 → 预览将恢复的内置显示/顺序、字号、自定义命令数量及与当前配置的差异 → 用户确认 → 一次性整体替换。预览须明确显示现有自定义命令中会消失的数量；用户可在确认前先导出当前配置备份。取消或校验失败保持当前配置不变。导入/导出采用浏览器本地文件，不上传。

“恢复默认”只恢复内置命令的显示状态、内置排序和扩展字号，不删除、改写或重新排序自定义命令。此操作先展示影响范围。用户若需要彻底恢复，可通过导入自行保存的配置实现；本版本不额外加入“一键清空自定义”操作。

## 验收重点

1. Chrome 真实 GitHub 页面上的普通 Issue、多正文框 Issue Form、README 编辑器各自仅有对应入口。原生编辑/预览/撤销流程继续工作，设置变更不改正文；Edge 实页仍是原验收记录中的未验证项，不在文档里宣称通过。
2. 五种 Alert 在同一二级页；Details、Keyboard、Diff 在一级。菜单只有图标和短名称，键盘、点击、返回、Escape 和焦点恢复都可操作；Issue 弹窗右侧、页面滚动、深浅主题和 200% 缩放下不跳动、不截断关键操作。
3. 隐藏及排序在对应层级生效；内置模板固定，自定义命令可增删改、排序、选择内置图标，并按选区与光标标记插入。对错误标记、重复光标、非法字号、超限字段与不合法导入均给出可定位错误，不破坏原配置。
4. 浏览器扩展图标点击能打开选项页；扩展管理页“选项”也可打开。菜单里没有设置项。配置在当前浏览器配置文件内对不同 GitHub 仓库生效，导出的 JSON 不包含编辑内容。
5. 以真实 GitHub 页面作为主要验收接缝；模板解析、导入校验、配置迁移可用少量针对性单元测试。不能只凭本地夹具宣称 Chrome/Edge 实页兼容。

## 本版采用的默认决策

用户要求按本设计完成实现，本版采用此前建议的六项默认行为：

1. 全部命令隐藏时，网页增强按钮隐藏，浏览器图标仍能进入选项页。
2. JSON 导入预览后整体替换，不提供合并。
3. “恢复默认”只重置内置显示/顺序和字号，保留自定义命令。
4. 自定义命令可以临时隐藏。
5. 选项修改立即同步到已打开的 GitHub 页。
6. 自定义命令最多 50 条、名称最多 40 字符、模板最多 10 KB。

后续若调整其中一项，应同时更新设置迁移规则、用户说明与相应验收场景。
